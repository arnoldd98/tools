# Day Strip, Day Pages and Spending Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the single-page Japan trip tracker into a hash-routed viewer with a horizontal day strip, per-day pages (Next up, timeline, spending, stay, notes) and yen/SGD spend tracking, without touching the GitHub sync flow.

**Architecture:** Pure logic moves into `japan-trip/lib.js` (data normalisation, money, next-up, routing) and HTML-string rendering into `japan-trip/views.js`; both are ES modules unit-tested with `node --test`. `japan-trip/app.js` becomes a module that owns state, localStorage draft, GitHub sync, hash routing and delegated DOM events, and calls `views.js` to fill `#top` and `#view`. `trip.json` grows optional fields (`fx`, `info`, `day.stay`, `day.spends`, `item.place/note/price`) and old files are normalised on load.

**Tech Stack:** Plain HTML/CSS/JS (ES modules, no build), `node --test` (Node 22) for unit tests, GitHub Pages, `python3 -m http.server` for preview.

**Spec:** `docs/superpowers/specs/2026-11-04-day-pages-design.md`

## Global Constraints

- No build step, no framework, no npm dependencies. Site must work from `python3 -m http.server -d . 8000` → `http://localhost:8000/japan-trip/`.
- Routes: `#/` home, `#/day/<dayId>` day page, `#/money` money view. Unknown day id falls back to `#/`.
- Spends stored as integer yen in `day.spends`; SGD derived at display time: `home = yen / fx.jpyPerHome`.
- Default `fx` when missing: `{ "home": "SGD", "jpyPerHome": 115, "updatedAt": null }`.
- SGD display: `S$` prefix; whole dollars when ≥ 100, else 2 decimals. Yen display: `¥` + thousands separators.
- Categories, in this order: `food`, `transport`, `shopping`, `tickets`, `stay`, `other`. Default `food`.
- `items[]` array order is authoritative. Render never sorts items. Quick-add inserts a timed stop before the first stop with a later time, appends an untimed one.
- A spend logged from home on a date with no day entry creates a day for today (empty items, city `""`) and logs there.
- Maps link: `place.maps` if present, else `https://www.google.com/maps/search/?api=1&query=` + `encodeURIComponent(name + ", " + address)` (address omitted if empty). Links use `target="_blank" rel="noopener"`.
- Today = `new Date().toLocaleDateString('en-CA')` (local date, `YYYY-MM-DD`). Keep.
- Reuse the CSS tokens in `style.css` (`--bg --card --ink --muted --line --accent --ok --today`); light and dark both.
- All user text goes through `esc()` before entering HTML.
- Text inputs never re-render on keystroke; saves happen on `change`/`submit` as today.
- Commit after each task with the trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. Spend amount typed as `1,200`, `¥1200`, `1200.5`, `0`, `-5` or blank: accept the first three as 1200 / 1200 / 1200 (digits only, truncated), reject the rest with a status message and no state change. → Task 2 `parseYen` tests.
2. Exchange rate typed as `0`, `-1`, `abc` or blank: rejected, stored rate kept, no `Infinity`/`NaN` on screen. → Task 2 `validRate` tests.
3. Pre-change `trip.json` (no `fx`, `info`, `spends`, `stay`, `place`) loads and renders every view with no thrown error. → Task 1 `normalise` tests, Task 5 render-with-legacy-data tests.
4. Item text, place name, spend label containing `<`, `&`, `"`: shown literally, never parsed as HTML. → Task 4 escaping test.
5. Hash pointing at a deleted or unknown day (`#/day/nope`) or garbage (`#/xyz`): home view renders, no error. → Task 2 `parseRoute` tests, Task 6 fallback step.

**Interfaces:**
- Produces:

  - `normalise(data: object|null) → State` where `State = { title: string, updated?: string, fx: Fx, info: InfoSection[], days: Day[] }`, `Day = { id, date, city, stay?: Place & {note?}, items: Item[], spends: Spend[], notes: string }`, `Item = { id, time, text, done: boolean, place?: {name, address, maps}, note?, price? }`, `Spend = { id, yen: number, label, category, at }`.   - `fmtBoth(yen, fx) → string` → `'¥1,200 ≈ S$10.43'`.

### Task 2: Remaining pure logic

**Files:**

**Interfaces:**
- Consumes: Task 1 types.
- Produces:
  - `parseYen(input: string) → number|null`: strip everything except digits before the first `.`; return the integer if > 0 else `null`.
  - `validRate(input: string|number) → number|null`: `Number(input)` if finite and > 0 else `null`.
  - `nextUp(day: Day) → Item|null`: first item with `!done` in array order.
  - `dayTotal(day) → number`, `tripTotal(state) → number`, `byCategory(state) → Record<category, number>` (every category key present, zero if none).
  - `mapsUrl(place: {name?, address?, maps?}) → string` per Global Constraints.
  - `insertItem(items: Item[], item: Item) → Item[]` new array per the insertion rule (`time` compared as `'HH:MM'` strings; items with empty `time` are never "later").
  - `parseRoute(hash: string) → { view: 'home' } | { view: 'day', id: string } | { view: 'money' }`. `''`, `'#'`, `'#/'`, `'#/xyz'` → home. `'#/day/d3'` → `{view:'day', id:'d3'}`. `'#/money'` → money.
  - `tripPhase(days: Day[], today: string) → { phase: 'none' } | { phase: 'before', daysToGo: number, first: Day } | { phase: 'during', day: Day|null } | { phase: 'after' }`. `during` with `day: null` means today is between first and last dates but has no entry. Days with empty `date` are ignored. `daysToGo` is whole calendar days from `today` to `first.date` (UTC date math on the `YYYY-MM-DD` strings).
  - `ensureDay(state: State, date: string, uid: () => string) → Day`: existing day with that date, else pushes `{ id: uid(), date, city: '', items: [], spends: [], notes: '' }` into `state.days` and returns it.
  - `parseFxRate(json: unknown) → number|null`: expects frankfurter shape `{ rates: { JPY: number } }`; returns `validRate(json.rates.JPY)`.
  - `FX_URL = 'https://api.frankfurter.app/latest?from=SGD&to=JPY'`.
